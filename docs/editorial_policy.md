# CCT Lab 編集方針

この文書は、CCT Lab の記事を「何のために作るか」と「何を満たせば良い記事とするか」を定義する。
記事構成のテンプレートではなく、企画・調査・執筆・リライト・削除判断の目的関数である。

## 1. 記事の目的

CCT Lab の記事の第一目的は、困りごとを持って検索・訪問した読者に、

**「そういうつながり方をしていたのか」**

という発見を渡すことである。

記事は次の4つを順番に達成する。

1. 読者の疑問・困りごとにきちんと答える
2. 単発の原因ではなく、生活の中の循環として見えるようにする
3. その見立てを、研究・観察・必要に応じた別理論の視点から厚くする
4. 読者が自分の生活で「どこを観察するか／どこを少し変えるか」を持ち帰れるようにする

SEOは目的ではない。SEOは、困っている人と記事を出会わせる手段である。
AdSense等の収益も目的そのものではなく、役立つ記事が読まれた結果として生じる。

## 2. CCT Lab で読む理由

論文の要約だけなら、検索エンジンや汎用AIでも作れる。
CCT Lab の独自価値は、研究の断片を生活の一周へ戻して読むことである。

例：

忙しい
→ 頭が疲れる
→ 手軽な刺激が魅力的になる
→ 短い動画を見る
→ 就寝が遅れる
→ 翌日さらに疲れる
→ また手軽な刺激へ寄る

記事で最も価値があるのは、個々の矢印を読者が「自分にもある」と理解できることである。

CCTを本文末尾に説明として追加するのではなく、記事そのものの読み解き方として使う。

## 3. 不協（ディゾナンス）と解決（レゾリューション）

### 不協（ディゾナンス）

不協は、単なる「悪い状態」「症状」「悪習慣」の名前ではない。

**ある状態・行動・条件が、次の乱れを呼び、その連鎖が自己強化していく関係や作用**を不協として読む。

したがって、
- スマホ
- 夜更かし
- 空腹
- 疲労

そのものを一律に悪者にしない。

「疲労 → 短期報酬を求める → 動画 → 就寝後退 → 翌日の疲労」のように、
何が次を呼んでいるかを見る。

### 解決（レゾリューション）

解決は、一般的に「健康に良い行動」の一覧ではない。

**不協の連鎖へ介入し、その次の状態や行動を変える候補**である。

解決を入れた後に本当に次の状態が変わったかを観察し、
変わらなければ仮説を見直す。

Tune は一度で正解を当てることではなく、

観察
→ 仮説
→ 一点を変える
→ 次の状態を見る
→ また調整する

という反復である。

## 4. 記事の情報レイヤー

記事では、異なる情報レイヤーを混同しない。

### A. 現代の研究・医学・心理学・行動科学など

研究で実際に測定された対象、条件、結果を根拠として使う。
一つの論文を記事の主役にする必要はない。
一つの生活上の疑問を理解するために複数の研究を使ってよい。

### B. 別の理論体系・伝統的な見方

東洋医学などは、現代医学の「追加証明」として扱わない。

価値があるのは、
**異なる理論体系でも、人間を長く観察した結果として似たまとまりを捉えていることがある**
という比較視点である。

記事テーマに実質的な厚みを与える場合は、十分に説明してよい。
単に「気滞です」「脾胃です」と付け足して文字数を増やす使い方は禁止する。
現代生理学の機序と同一視しない。

### C. CCTによる読み解き

研究同士をつないだ生活上の循環は、CCTの仮説・観察モデルである。
研究が循環全体を証明したかのようには書かない。

ただし本文中で毎回「これはCCT仮説です」とメタ説明して読み味を壊さない。
必要な境界は文章上自然に示し、詳細な研究条件・限界は Research Note に逃がしてよい。

### D. 読者が試せる観察・調整

「治る」「必ず改善する」という処方ではなく、
自分の循環を確かめる小さな観察・介入候補を示す。

## 5. 読み物としての基準

記事は論文解説書ではなく、読み物である。

- 具体的な日常場面から入ってよい
- 実在しない運営者体験・患者体験・インタビューを事実として捏造しない
- 一般化した場面は自然に描写してよい
- 「この記事では〜を解説します」のようなメタ導入を避ける
- 「CCTでは〜」「研究では〜と言えません」を連発しない
- 安全上必要な注意は書くが、編集上の予防線を本文の主役にしない
- 一つの節に一つは、読者の理解が一段進む内容を置く
- 研究の要約だけで終わらない
- 読後に「知識を得た」だけでなく「自分の一周が少し見えた」が残ることを目指す

## 6. 記事の長さ

文字数はSEOのために決めない。

標準的な記事では、生活場面・背景・複数視点・CCTの循環・実践・Research Noteまで十分に扱うと、
**日本語本文4,000〜6,500字程度**になることを目安とする。

これはノルマではない。

- 3,000字で十分なら無理に5,000字へ伸ばさない
- 7,000字必要なテーマを機械的に削らない
- 「東洋医学節を足して文字数を稼ぐ」などは禁止
- 短くした結果、独自の考察や生活描写まで消すのも禁止

readingTime は文字数を作る目的ではなく、読者向けのおおよその案内とする。

## 7. SEO・マーケティング

新規記事は「珍しい論文」から決めない。

優先順位は、

1. 実際の困りごと・検索意図
2. 既存ページの検索実績や関連クエリ
3. CCTとして面白い循環が描けるか
4. 十分な根拠が集められるか
5. 既存記事と役割が重ならないか

とする。

検索者の疑問には記事前半で答える。
その後にCCT独自の価値を足す。

理想的な導線は、

検索
→ 記事単体で満足
→ 「循環で見ると面白い」と感じる
→ 関連する困りごとページ／CCT概念へ進む
→ 将来の観察・シミュレーション機能へ進む

である。

## 8. SEOのためにやらないこと

- キーワードを見出しへ機械的に反復する
- 検索需要の薄いテーマを「既存と被らないから」という理由で量産する
- 一論文一記事をルールにする
- 似た検索意図のページを大量に作る
- 文字数をランキング要因だと考えて水増しする
- AIで公開ページ数を増やすこと自体をKPIにする

## 9. 医療・健康記事の安全

CCT Lab は医療機関ではなく、診断・治療・服薬変更を行わない。

ただし、安全性を理由に本文を注意書きだらけにしない。

- 強い、急性、長引く、生活への影響が大きい症状は医療相談を優先
- 治療中・服薬中の人へ自己判断の中止・変更を勧めない
- 研究対象と一般読者を同一視しない
- 関連を因果と書かない
- 研究で測っていない結果へ飛躍しない
- 詳細な対象・条件・限界は Research Note にまとめる

## 10. Research Note

Research Note は本文の「言い訳」ではなく、裏側の品質保証である。

本文は読みやすく保ち、末尾で以下を確認できるようにする。

- 論文タイトル
- 著者
- 年
- 研究種別
- 対象・条件
- 主な結果
- 何は言えないか
- 一次資料リンク

記事によって複数の paper-summary を使ってよい。

## 11. 記事の削除・統合

既存記事は、検索資産を不用意に捨てない。

### URLを維持してリライト
- Search Consoleで表示・クリック実績がある
- 外部・内部リンクの受け皿になっている
- 検索意図が明確
- テーマ自体に価値がある

### 統合候補
- 検索意図がほぼ同じ記事が複数ある
- 片方が薄く、もう片方に統合した方が読者価値が高い
- 統合時は可能なら適切なリダイレクトを行う

### 削除候補
- インデックスされていないことを確認できる
- 検索実績がない
- 他記事と重複している
- CCTとして独自価値を付けにくい
- 将来もハブや内部リンクの役割がない

Search Consoleで表示がないだけでは「未インデックス」と断定しない。

## 12. AI生成フロー

AIは「記事量産機」ではなく編集部として使う。

原則：

企画
→ 根拠調査
→ 記事設計
→ 執筆
→ 根拠照合・編集
→ 公開

新規記事の自動公開はしない。

企画では読者の問題と記事の発見を決め、
調査では一次資料を確認し、
執筆では構成を自由に最適化する。

テンプレートは最低品質を守るガードレールとして使う。
テンプレートそのものを完成記事の形にしない。

## 13. 公開前の問い

公開前に最低限、次を確認する。

- 誰のどんな困りごとに答えているか
- 記事を一文で言うと、読者にどんな発見を渡すか
- CCTでなければ書けない部分はどこか
- 研究の要約だけになっていないか
- 別視点は本当に理解を厚くしているか
- メタ説明・注意書きが読み物を壊していないか
- 似た既存記事と役割が分かれているか
- 読後に次に観察するものが見えるか
